# Вариант 17. Заказы на доставку

Самостоятельный учебный проект Django. Данные: SQLite → SQL → sqlite3 → view → context → шаблоны. ORM не используется.

## Запуск в PowerShell

Из папки delivery_service:

```powershell
python -m pip install -r requirements.txt
python seed.py
python manage.py runserver 127.0.0.1:8017 --insecure
```

Открыть http://127.0.0.1:8017/ . Флаг `--insecure` нужен только локально: DEBUG=False сохраняет понятную страницу 404, а флаг разрешает Django отдавать учебные статические файлы. В комплекте уже есть база с 4 зонами и 8 доставками; seed.py добавляет демонстрационные данные только в пустые таблицы. Локальная папка .deps, если присутствует, содержит зависимости для проверки на этом компьютере.

## Проверка

```powershell
python manage.py check
python manage.py test
```

Проверяются страницы, JOIN, дата, 404, ошибки БД, пустые таблицы, валидация, фильтры, сортировка, LIMIT, изменение SQLite, COUNT и HAVING.

## Демонстрация

1. Главная: число доставок читается из COUNT, ссылки ведут к зонам и заказам.
2. /zones/: 4 зоны, типы и дневная вместимость.
3. /deliveries/: карточки из include; три статуса оформляются через if; date, default, upper, truncatechars и length используются в шаблонах.
4. /deliveries/?boxes=3 и ?boxes=10: разные результаты параметризованного SQL. ?boxes=999: пустой результат. ?boxes=abc: понятная ошибка 400.
5. /deliveries/?sort=boxes_desc&limit=2: 25 и 20 посылок. Сортировка — только из белого списка, LIMIT передаётся параметром.
6. /deliveries/food-box/: все поля заказа и зоны. Кнопка скрывает и показывает зону через подключённый JS.
7. /deliveries/missing/: оформленная 404.
8. /deliveries/statistics/?minimum=2: COUNT, SUM, GROUP BY, HAVING. minimum=3 оставляет продукты и технику, minimum=4 даёт пустую таблицу.
9. Логотип PNG и собственный CSS подключены через static.

## SQL и актуальность данных

Запрос списка доставок записан прямо в deliveries/views.py в учебном стиле: conn.execute → fetchall → conn.close → context → render. Соединение создаётся через connect_db() из deliveries/db.py с sqlite3.Row; finally гарантирует его закрытие даже при ошибке. Остальные запросы загружаются из sql/queries.sql; в этом файле также сохранён эквивалент запроса списка для демонстрации SQL. Соединение закрывает closing; чтение открывает только существующую БД (mode=rw). Даты преобразуются в datetime для фильтра date. Запросы выполняются заново при каждом запросе страницы. Ошибки sqlite3 обрабатываются общим декоратором: ответ 503 без технических подробностей.

Для ручной проверки SQL без внешних программ:

```powershell
python -c "import sqlite3; c=sqlite3.connect('data/deliveries.db'); print(c.execute('SELECT goods_type, COUNT(*) FROM deliveries GROUP BY goods_type HAVING COUNT(*) >= ?', (2,)).fetchall()); c.close()"
```

Изменение зоны (после проверки можно вернуть имя):

```powershell
python -c "import sqlite3; c=sqlite3.connect('data/deliveries.db'); c.execute('UPDATE zones SET name=? WHERE id=?', ('Обновлённый центр',1)); c.commit(); c.close()"
```

Обновить страницу зон и карточку food-box — новое имя появится без изменения HTML.
Для проверки HAVING добавить запись SQL через sqlite3, задав уникальные id и slug; после добавления четвёртого заказа типа «продукты» группа появится при minimum=4. Автоматический тест делает это в копии базы, не меняя исходные записи.

Для демонстрации ошибки БД остановить сервер, временно переименовать data/deliveries.db, запустить сервер и открыть страницу: ответ 503. Затем вернуть файл на место. Настоящая база никогда не удаляется обработчиком.

## Основные файлы

- delivery_service/settings.py, urls.py — настройки и корневая маршрутизация.
- homepage/, zones/, deliveries/ — три приложения с функциональными view.
- deliveries/db.py — sqlite3, параметры, белый список сортировки, закрытие соединений.
- sql/schema.sql, queries.sql — схема и исполняемые запросы.
- templates/base.html — общий интерфейс; templates/404.html, database_error.html — ошибки.
- static/ — CSS, JS, логотип.

Локальный учебный сервер; SECRET_KEY демонстрационный. Миграции и Django admin для решения не требуются.


## Изменение статуса доставки

Откройте карточку заказа, выберите «Принят», «В пути» или «Доставлен» и нажмите «Сохранить статус». Изменение сохраняется в SQLite и отображается в карточке и списке. Можно выбрать любой из трёх статусов, в том числе исправить ошибочный выбор.

Сохранение выполняется POST-запросом с CSRF-токеном. Сервер проверяет значение по белому списку, выполняет параметризованный UPDATE и перенаправляет на карточку. GET-запросы данные не меняют. Дополнительно проверены сохранение всех статусов, неправильный ввод, CSRF, отсутствующий заказ и недоступная БД. В учебном приложении авторизация не предусмотрена: статус может менять любой посетитель, имеющий доступ к сайту.

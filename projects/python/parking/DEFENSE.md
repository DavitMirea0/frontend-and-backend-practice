# Подготовка к защите

Перед демонстрацией запустить приложение:

```sh
docker compose up --build -d
docker compose ps
```

В списке контейнеров должно быть состояние healthy. Страница приложения:
http://127.0.0.1:8000. Учётную запись охраны нужно создать заранее:

```sh
docker compose exec parking python manage.py account guard@example.org --role operator
```

Пароль вводится в терминале. Для новой учётной записи пользователя пароль
задаётся при регистрации на странице.

## Что показать

1. Без входа открыть сводку, карту мест и прогноз на выбранную дату.
2. Войти как пользователь, добавить автомобиль, создать и отменить бронь.
3. Под другой учётной записью показать, что чужие автомобили и брони не видны.
4. Войти как охрана. Оформить въезд, повторить его и получить ошибку, затем оформить выезд.
5. Открыть /docs. Для защищённых запросов получить токен через /api/auth/login
   и вставить его в Authorize. Без токена сервер отвечает 401, при недостаточных
   правах — 403.
6. Запустить `python -m pytest -v` в окружении с установленными зависимостями.
   В проекте 22 теста; пользовательская база при запуске тестов не меняется.
7. Запустить `python tools/load_test.py --requests 200 --workers 10`.
   В результате будут число ошибок, запросы в секунду, медиана и p95 времени ответа.
8. Открыть /health/ready и показать `docker compose logs --tail=30 parking`.
   Затем показать Dockerfile, compose.yaml и команду резервного копирования в DEPLOYMENT.md.

## Что объяснить

**Права.** Пользователь работает со своими машинами и бронями. Охрана оформляет
въезд и выезд. Администратор также управляет зонами и имеет доступ к списку
пользователей. Категория посетителя (студент, преподаватель и т. д.) не даёт
служебных прав.

**Пароли и вход.** Пароли хэшируются PBKDF2 SHA256 с солью и 600000 итераций.
Токен сессии случайный, в базе хранится его SHA256. Срок сессии — 8 часов.
После выхода токен больше не принимается.

**Прогноз.** Используются те же дни недели за последние восемь недель.
Результат хранится в памяти до 30 секунд. В кэше не больше 128 записей.
Праздники и расписание занятий в прогноз не включены.

**Состояние приложения.** /health/live проверяет, что процесс отвечает.
/health/ready дополнительно обращается к БД. Состояние unhealthy сообщает
об ошибке проверки, но само по себе не перезапускает контейнер.

**Границы проверки.** Проверен локальный контейнерный запуск. Для HTTPS нужны
домен и сервер. PostgreSQL, отказоустойчивый кластер и внешние оповещения
не проверялись. Прогноз построен на тестовой истории из seed.py.

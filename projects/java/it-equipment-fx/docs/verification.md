## Автоматические проверки

Финальный результат обновления с каскадом: **11 проверок, 11 пройдено, ошибок и пропусков нет**. Использован отдельный PostgreSQL 16 в Docker на порту 55439; рабочая база пользователя не изменялась.

- `RequestServiceTest`: 5 проверок правил сервисов и коллекций.
- `RequestFilterTest`: 2 проверки совместных фильтров и поиска.
- `JavaFxTest`: загрузка всех FXML, применение CSS, поиск и фильтры, валидация формы, фоновое сохранение с репозиторием в памяти, предварительное заполнение, допустимые статусы, снимки обычного и уменьшенного окна.
- `PostgresIntegrationTest`: предусмотрена проверка реальных CRUD, ограничений PostgreSQL и чтения созданного XLSX обратно через POI.
- Дополнительный метод `JavaFxTest` проверяет загрузку данных через производственную конфигурацию при заданном `DB_URL`.

Проверены реальные JDBC CRUD, ограничения, экспорт XLSX и загрузка PostgreSQL в JavaFX. Новый тест создаёт заявки всех пяти статусов, удаляет сотрудника через UserService и проверяет отсутствие всех его заявок, сохранность другого сотрудника и его заявки, а также ошибку повторного удаления. Тестовые записи очищаются в finally.

Сначала тестовая база была создана по старой схеме КР 1 с ON DELETE RESTRICT. Миграция 03-cascade-delete.sql применена дважды; после неё сохранились исходные 5 сотрудников и 10 заявок. Затем выполнены тесты с новым поведением.

## Сборка в текущей среде

Зависимости самого приложения доступны и исходники скомпилированы. Для сборки JAR использована команда `mvn test jar:jar`: обычная фаза `package` дошла до загрузки зависимостей плагина копирования, но загрузка части Maven Central завершилась ошибками DNS/соединения. В поставляемую папку `app/lib` скопированы разрешённые runtime-зависимости из Maven-кэша; JUnit и javafx-swing туда не включены. Обычный `mvn package` оставлен в проекте для среды с доступным Maven Central.

Финальные результаты тестов сохранены в `docs/test-results/`. Снимки графических тестов — `docs/preview/`; postgresql-data.png показывает чтение тестовой PostgreSQL, остальные снимки используют репозиторий в памяти.

## Архив преподавателя

Изучен `student-hub-suite.zip`, в том числе `javafx-client`, фоновые задачи, таблицы и Compose. Демонстрационный JavaFX-клиент использует REST API, а собственная КР 2 по заданию должна обращаться к PostgreSQL через JDBC. В этом проекте соблюдён прямой JDBC-путь и добавлены FXML-окна.

Полное развёртывание демонстрационного комплекса преподавателя не подтверждено. Для проверки обновления использован отдельный контейнер PostgreSQL 16; рабочий Compose пользователя не пересоздавался. Проверить у себя: запустить Docker Desktop, выполнить `start-db.cmd`, затем `run.cmd`, дождаться 5 сотрудников и 10 заявок на новой учебной базе. Если используется прежняя база КР 1, количество соответствует её текущим данным.

Интерактивный системный FileChooser и полный сценарий всех подтверждений удаления не автоматизированы; проверьте их по сценарию из `defense.md`. Проверка XLSX с реальной базой выполнена интеграционным тестом.

## Проверка запуска Compose

В отдельном проекте it-equipment-compose-check проверен запуск из актуального compose.yaml с новым томом на порту 55439. PostgreSQL стал healthy, migrate применил SQL и завершился с кодом 0. Затем внешний ключ тестовой базы возвращён в ON DELETE RESTRICT и проверен повторный запуск migrate: обновление успешно, код 0. Рабочая база пользователя не изменялась.

# Заявки на выдачу IT-оборудования — КР 2

Настольное приложение JavaFX. Сохранены сущности, бизнес-правила и схема PostgreSQL из КР 1. Интерфейс работает через Service → Repository → JDBC; отдельный backend для приложения не требуется.

## Быстрый запуск на Windows x64

1. Распакуйте весь архив в доступную для записи папку. Не запускайте файлы прямо из ZIP.
2. Запустите Docker Desktop и дождитесь его готовности.
3. Дважды щёлкните `start-db.cmd`. Он запускает базу и ждёт успешного завершения миграции.
4. Запустите `run.cmd`. Откроется окно с вкладками «Заявки», «Сотрудники», «Статистика».

В архив включены собранная программа (`app/`), библиотеки и переносимая Java 17 (`runtime/`). Устанавливать Maven и менять системную Java для запуска готовой сборки не требуется. Первый запуск Docker требует доступа к интернету для загрузки PostgreSQL.

JavaFX запускается на компьютере. В Docker находится только PostgreSQL. Закрытие окна завершает клиент, но база продолжает работать. Остановить базу: `docker compose stop db`. Данные остаются в именованном томе.

## Подключение к базе КР 1

Настройки находятся в `config/database.properties`:

```properties
db.url=jdbc:postgresql://localhost:55433/it_equipment
db.user=it_app
db.password=it_demo_password
```

Это параметры учебной базы из поставляемого Compose. При использовании другой существующей базы укажите её адрес, пользователя и пароль. Пересобирать программу не нужно. Переменные окружения `DB_URL`, `DB_USER`, `DB_PASSWORD` имеют приоритет над файлом. Старые переменные окружения могут поэтому перекрывать ваши изменения.

Compose использует имя проекта `it-equipment` и том `it-equipment_it_equipment_data`. При стандартном запуске проекта КР 1 из папки `it-equipment` это прежний том с данными. Если КР 1 запускалась с другим именем проекта, сначала проверьте `docker volume ls`: нельзя считать новый пустой том прежней базой. Можно продолжить использовать уже запущенный PostgreSQL КР 1, указав его опубликованный порт в конфигурации, без запуска второго контейнера.

В старом Compose КР 1 порт базы мог быть не опубликован. Для подключения с Windows добавьте к сервису `db` публикацию `127.0.0.1:55433:5432` и пересоздайте контейнер с сохранением тома. Если этот порт уже занят другой базой, выберите свободный и измените `db.url` соответственно.

SQL в `sql/01-schema.sql` и `sql/02-seed.sql` автоматически выполняется только при первом запуске пустого тома. Начальные данные: 5 сотрудников, 10 заявок, 5 статусов. Изменение `POSTGRES_PASSWORD` в Compose не меняет пароль уже созданной базы. Не используйте `docker compose down -v` для исправления подключения: эта команда удаляет данные.

## Работа в приложении

- Создайте сотрудника во вкладке «Сотрудники» или выберите существующего при создании заявки.
- Для новой заявки выберите сотрудника и оборудование, укажите количество 1–10 и обоснование до 500 символов.
- Выберите строку таблицы для просмотра, изменения, смены статуса или удаления. Удаление требует подтверждения.
- Поиск проверяет обоснование, ФИО и отдел сотрудника без учёта регистра. Фильтры статуса и оборудования применяются одновременно с поиском.
- Нажмите заголовок столбца для сортировки; повторное нажатие меняет направление. Количество сортируется как число, дата — как дата. Shift позволяет выбрать несколько столбцов сортировки.
- «Экспорт показанных в Excel» сохраняет текущие отфильтрованные и отсортированные заявки и связанных с ними сотрудников. Путь выбирается в системном диалоге. Отмена диалога ничего не записывает.
- Статистика рассчитывается по всему загруженному набору, независимо от фильтров таблицы. «Обновить» повторно читает базу.

Переходы статусов: новая → одобрена / отклонена / отменена; одобрена → выдано / отменена. Остальные статусы конечные. Изменять поля можно только у новой заявки. Удалять одобренную или выданную заявку нельзя. При удалении сотрудника удаляются все его заявки. Email сотрудника должен быть уникальным; проверки выполняются и в сервисах, и ограничениями базы там, где применимо.

## Исходники и сборка

Нужны JDK 17+ и Maven. Из папки проекта:

```powershell
mvn clean package
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1
```

После этого `run.cmd` использует обновлённые JAR. Альтернативный запуск из исходников: `mvn javafx:run`. Переносимая Java в `runtime/` предназначена для запуска, это не полный JDK для компиляции. При сборке для Linux/macOS Maven должен загрузить JavaFX для соответствующей ОС; готовая папка `app/lib` в этом архиве предназначена для Windows x64.

Модульные проверки: `mvn test`. Проверки интерфейса требуют графического рабочего стола и переменной `FX_TEST=true`. Интеграционные проверки запускаются только при явном задании `TEST_DB_URL`; используйте отдельную тестовую базу со схемой проекта. Для проверки загрузки базы через окно также задайте `DB_URL`. Тест JDBC создаёт свои временные записи и удаляет их в `finally`.

## Структура

```text
src/main/java/ru/mirea/project/
  EquipmentApplication.java, Launcher.java — запуск
  controller/ — действия пользователя и обновление окон
  model/ — сотрудники, заявки, типы и статусы
  service/ — бизнес-правила и поиск
  repository/ — интерфейсы и JDBC-реализации
  exception/ — собственные исключения
  util/ — настройки, фоновые задачи, экспорт и общие функции UI
src/main/resources/view/ — FXML главного окна, вкладок и форм
src/main/resources/css/ — оформление
config/ — изменяемые настройки подключения
sql/ — схема и демонстрационные записи
docs/ — ER-диаграмма, объяснения и проверка требований
examples/ — пример Excel из демонстрационных данных КР 1
```

Материалы для защиты: `docs/defense.md`. Соответствие заданию и ограничения проверки: `docs/verification.md`.

## Если не запускается

- Docker недоступен: запустите Docker Desktop, затем повторите `start-db.cmd`.
- Отказ входа PostgreSQL: проверьте пользователя, пароль и переменные окружения. Это ошибка аутентификации, а не отсутствие таблиц.
- Нет таблиц: подключитесь к базе КР 1 со схемой либо инициализируйте новую учебную базу SQL-скриптами.
- Ошибка Java 8: убедитесь, что распакована папка `runtime` и используется `run.cmd` из этого архива.
- Ошибка экспорта: закройте целевой файл в Excel и выберите доступную для записи папку.

Библиотеки находятся в `app/lib`; переносимая Java сохраняет лицензионные файлы в `runtime/legal`. Не удаляйте эти папки из распространяемого комплекта.

## Обновление: каскадное удаление сотрудника

Перед первым запуском новой версии выполните `start-db.cmd`: после запуска базы он применяет `sql/03-cascade-delete.sql`. Для уже работающей базы можно отдельно запустить `update-db.cmd`. При ошибке обновления не продолжайте демонстрацию удаления: проверьте вывод скрипта.

Миграция заменяет внешний ключ на `ON DELETE CASCADE`, не удаляя существующих сотрудников и заявок. Повторное применение допустимо. Если используется PostgreSQL вне поставляемого Compose, выполните `sql/03-cascade-delete.sql` в своей базе через psql или SQL-редактор с правами владельца таблицы.

После обновления удаление сотрудника удаляет ВСЕ его заявки независимо от статуса. PostgreSQL выполняет удаление сотрудника и зависимых заявок в одной операции: частичного удаления не происходит. Заявки других сотрудников остаются. Подтверждение в интерфейсе предупреждает об этом. Отдельное удаление одобренной или выданной заявки по-прежнему запрещено сервисом; это другое действие.

Изменения только файла `01-schema.sql` недостаточно для существующего Docker-тома, поэтому миграцию нужно применить явно. Удалять том или повторно загружать начальные данные не требуется.

## Запуск командой Docker Compose

Из папки с compose.yaml выполните:

```powershell
docker compose up
```

Compose запускает PostgreSQL и сервис migrate. После готовности базы migrate выполняет 03-cascade-delete.sql и завершается с кодом 0. Это успешное завершение одноразовой задачи, не ошибка. При ошибке миграции psql завершится с ненулевым кодом; проверьте вывод и параметры доступа.

Дождитесь сообщения `migrate exited with code 0`, затем запустите `run.cmd` из другого окна или Проводника. JavaFX остаётся локальным Windows-приложением: docker compose up запускает базу и миграцию, но не графическое окно.

Для работы контейнеров в фоне используйте `docker compose up -d`, затем проверьте `docker compose logs migrate` и `docker compose ps -a`. Завершение migrate с кодом 0 ожидаемо. Для остановки — `docker compose stop`; том с данными сохраняется. В обычном режиме Ctrl+C в окне compose up останавливает запущенные им сервисы.

Миграция работает и с существующим томом: повторно загружать SQL начальных данных или удалять том не нужно. Для смены опубликованного порта задайте DB_PORT перед запуском Compose и соответственно измените порт в config/database.properties. Значение по умолчанию — 55433.

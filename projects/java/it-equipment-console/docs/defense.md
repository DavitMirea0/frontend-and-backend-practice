# Подготовка к защите

## Демонстрация за 5–7 минут

1. Запустить PostgreSQL и приложение. Пункт 8 показывает 5 сотрудников и 10 заявок.
2. В статистике показать: 5 сотрудников, 10 заявок, 17 единиц; новые — 4, одобренные — 2, выданные — 2, отклонённые — 1, отменённые — 1.
3. Найти заявки по обоснованию «Мониторы», затем по сотруднику «Иванова».
4. Отфильтровать новые заявки и ноутбуки. Показать обе сортировки.
5. Создать сотрудника с новым email и заявку на него. Запомнить выведенные ID: после тестов последовательность может иметь пропуски.
6. Ввести `abc` вместо ID: приложение предлагает повторить ввод. Попробовать количество 0: срабатывает правило сервиса.
7. Изменить новую заявку. Попробовать сразу выдать её — переход запрещён. Одобрить, затем выдать. Попробовать удалить выданную заявку — отказ.
8. На отдельной новой заявке показать удаление с подтверждением. Удалить сотрудника без заявок. Попытка удалить сотрудника с заявками запрещена.
9. Экспортировать Excel и открыть файл. Закрыть и заново запустить программу: данные сохранились.

## Ответы на вопросы

**Что делает Main?** Создаёт объекты репозиториев, сервисов и меню, передаёт зависимости. Бизнес-логики и SQL в нём нет.

**Инкапсуляция?** Поля моделей закрыты. Доступ — через геттеры; корректные изменения проводятся через сервисы. Неизменяемые модели не позволяют незаметно изменить объект после проверки.

**Интерфейсы и полиморфизм?** `RequestService` принимает `RequestRepository`, а не конкретный JDBC-класс. Один и тот же вызов выполняет JDBC в приложении и реализацию в памяти в модульных тестах. `CrudRepository<T>` задаёт общую форму CRUD.

**Зачем enum?** У статуса и оборудования конечный набор значений. `RequestStatus.canTransitionTo` описывает допустимые переходы. В БД значения enum хранятся строками и проверяются `CHECK`.

**Коллекции?** `List` хранит результаты запросов, `Set` — ID сотрудников для поиска, `LinkedHashMap` сохраняет порядок статистических показателей. Stream фильтрует и сортирует записи.

**Исключения?** Собственные исключения отделяют ошибки правил, отсутствие объекта и сбой хранения. Меню перехватывает ожидаемые ошибки и продолжает цикл. Ошибка числа обрабатывается при разборе ввода. Конец входного потока завершает приложение без аварии.

**Как работает JDBC?** `DatabaseManager` создаёт соединение, репозиторий готовит запрос, связывает параметры, выполняет его и преобразует строки `ResultSet` в модели. try-with-resources закрывает ресурсы даже при исключении.

**Statement и PreparedStatement?** `Statement` выполняет SQL-строку. `PreparedStatement` задаёт шаблон с параметрами, передаваемыми отдельно от SQL. Это защищает значения от интерпретации как SQL-кода и обеспечивает передачу типов.

**Ключи и ограничения?** PK идентифицирует запись, FK связывает заявку с сотрудником. UNIQUE защищает email, NOT NULL запрещает отсутствие обязательных значений, CHECK ограничивает строки, тип, статус и количество. Индекс по FK ускоряет обращения к заявкам сотрудника.

**Как сохраняется изменение?** Сервис проверяет данные, репозиторий выполняет параметризованный UPDATE. Изменение статуса проверяет также старый статус в WHERE. Каждая операция записи — один SQL-запрос с автокоммитом.

**Excel?** Apache POI создаёт настоящий `.xlsx`, содержащий данные, прочитанные репозиториями из PostgreSQL. Два листа содержат заявки и сотрудников, в заявках дополнительно выводится ФИО по user_id. Даты и числа имеют соответствующие типы ячеек.

## Предложение по распределению на четырёх участников

| Участник | Ответственность | Что объясняет |
|---|---|---|
| 1 | Модели, enum, сервисы | Инкапсуляция, правила, граф статусов |
| 2 | SQL, JDBC-репозитории | Связи, ограничения, PreparedStatement |
| 3 | Консольное меню, обработка ввода | Циклы меню, CRUD, исключения |
| 4 | Поиск, статистика, Excel, тесты | Коллекции, полиморфизм, экспорт |

Это предложенное распределение, а не сведения о фактическом авторстве. Впишите ФИО команды самостоятельно. Каждый участник должен понимать весь проект.

## Продолжение КР

В КР 2 JavaFX заменит ConsoleUi, а сервисы и репозитории сохранятся. В КР 3 REST-контроллеры будут вызывать сервисы. В КР 4 Android будет обращаться к REST API, а не напрямую к PostgreSQL. Предметная область остаётся прежней.
